Wren — a small self-hosted Discord bot

Role automation, welcomes and quick moderation for small communities. Slash commands only, no privileged intents, and a single SQLite file you can back up with cp.

Self-hosting guide Command reference
python ≥ 3.11 discord.py 2.4 sqlite · no external services 39 slash commands

What it does

Wren is deliberately small. Everything below is a slash command or a per-guild setting — there is no web dashboard and no account to create.

◧

Role automation

Self-assignable roles with a button panel, plus rules that grant a role when a member joins or reaches an age in the server.

✉

Welcomes & goodbyes

Templated join and leave messages with {user}, {count} and {inviter} placeholders. Per-channel, per-guild.

⚑

Quick moderation

Bulk delete, slowmode, timeout presets and a soft-ban list. Every action writes an audit line to a channel you choose.

⏱

Reminders

Natural-ish durations (10m, 2h, 3d) stored locally, delivered even after a restart.

⌗

Server insights

Member growth, join and leave counts, and channel activity over the last 7 or 30 days, rendered as plain text.

◇

No privileged intents

Message content is never requested. Wren cannot read your chat, so it needs almost no permissions to run.

Command reference

A subset of the 39 commands. All of them are slash commands and respect per-channel allow and deny lists.

CommandDescription
/helpList every command available to the caller, filtered by their permissions.
/pingRound-trip latency to the Discord gateway and the local database.
/role add <member> <role>Grant a role, respecting the role hierarchy.
/role panel [channel]Post or refresh the self-assignable role panel.
/welcome set <channel> <template>Set the join message for this server.
/purge <count> [member]Delete up to 100 recent messages, optionally filtered by author.
/slowmode <seconds> [channel]Set or clear slowmode on a channel.
/remind <duration> <text>DM the caller after the given duration.
/stats [days]Member and activity summary for this guild.
/config exportDump this guild's settings as JSON.

Self-hosting

Wren runs as an ordinary long-lived process. No container platform required — a VPS, a home server or any host that can keep a Python process alive will do.

  1. Clone and install. Only discord.py and aiosqlite are needed.
  2. Create the bot. In the Discord developer portal, add a bot to an application and copy its token. Enable no privileged intents.
  3. Fill in .env. The token, and optionally a home guild for instant command sync.
  4. Invite it. Generate an OAuth2 URL with the bot and applications.commands scopes.
  5. Run it. Behind systemd or a process manager, or nohup if you like living dangerously.
# install
git clone https://github.com/wrenbot/wren.git
cd wren
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt

# configure
cp .env.example .env
$EDITOR .env

# run
python bot.py

# .env
DISCORD_TOKEN=your-bot-token
GUILD_ID=            # optional: instant command sync
LOG_LEVEL=info
DATA_DIR=./data
TZ=UTC

Questions

The four that come up most often.

Does Wren read message content?

No. Every feature is a slash command or a button interaction, so the message-content intent is never requested. If the developer portal shows a privileged intent as enabled for Wren, that is a misconfiguration — it does not need one.

Where is my data stored?

A single SQLite file inside DATA_DIR. Nothing is sent anywhere else and there is no telemetry, so copying that file is a complete backup.

Can I run it for more than one server?

Yes. Each guild has its own settings row, and a single process comfortably serves a handful of small communities on a 256 MB host.

Something is broken — where do I report it?

Open an issue on GitHub with the version line printed at startup and the output of /help. Pull requests are welcome; keep them focused and add a changelog entry.
